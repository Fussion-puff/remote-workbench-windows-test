# Remote Workbench 开发任务拆分

初始拆分日期：2026-10-25。初始核对基线：`develop` 提交 `bebcbea1427c39f46f6f2fcb579a33f72c6b2797`，版本 `0.3.0a11`。

**2026-10-26 范围更新**：当前核对基线为 `develop` 提交 `4fc892e`，版本 `0.3.0a12`。Token/credits 计量仅用于手动运行的独立、可重复基准样本；Remote Workbench 自身的日常命令、编辑和测试路径不采集 token/credits 或模型费用，不因计量增加模型调用；日常工作流不在回复或 UI 中追加用量评估，也不以基准门槛阻止普通任务完成。此约定仅限 Remote Workbench 自身的执行与集成路径，不声明 Codex App 或模型服务如何记录账户用量。费用账本和脚本保留为测试辅助工具；完整操作记录与必要执行诊断照常保留。开发顺序聚焦目录模式、可靠性和证据；E2/E3 是按需启动的独立实验。功能正确性、develop CI 与 stable 发布规则仍是各自的验收要求。

本文将用户建议拆成可验证的工作包。状态仅表示本轮核对结果；“已复现”不表示已修复。每个实现任务单独提交，按依赖集成，不把六个方向合成一个大重构。

## 决策与边界

- 本地保留 Agent 控制、聊天工作区、任务归属与审计；用户显式选择远端执行目标。普通本地任务仍使用原生本地工具，不自动进入远端。
- 聊天身份、仓库来源、实际工作目录分别建模。未来支持不同仓库、同仓独立目录和显式共享同一实际目录。
- 将 direct 作为目标默认行为：先实现显式选项与协调机制，通过验收后再调整新建目标的默认值。已有 copy 目标保留原路径、任务和记录，不自动改绑或清理。
- 保留人工认证、Agent 复用现有 ControlMaster 的流程。失去可用连接时明确失败，不自动重新认证。目录限制和 skill 都不等于操作系统沙箱。
- 保留完整功能、编辑保护、审阅、作业停止和恢复能力。精简回复、工具入口数量和 skill 分别验收，不用隐藏功能换取成本数字；日常工作保留完整操作记录和必要执行诊断。
- Token/credits 计量限于手动运行的独立、可重复基准。Remote Workbench 自身的日常执行路径不采集用量或费用、不添加计量模型调用，也不在日常回复/UI追加用量评估；此约定不涵盖 Codex App 或模型服务的账户用量记录，也不阻塞普通任务完成。2% token 阈值与历史样本的口径和记录见[独立 Token 基准](token-budget.zh-CN.md)，不解释为费用百分比。
- 最初拆分完成本地最小复现；第一批现已由有文件边界的子 Agent 执行并经父级审阅、集成回归。远端目录默认值、全局安装入口和 stable 均未改变。

## 实践核对

初次核对时，四个本地最小案例均在基线 `bebcbea` 复现。使用临时文件、本地审计和执行远端脚本的本地测试适配器，没有连接真实 SSH，也没有读取凭据。复现脚本及 JSON 保存在本机 `.local/work/task-split-20261025/`，不作为公开运行日志提交。

| 问题 | 本轮证据 | 任务 |
|---|---|---|
| 搜索游标不前进 | 1024 字节结果预算、较多需 JSON 转义的上下文；连续两页 `next_cursor=0`，返回同一匹配 | C1 |
| 跳过信息丢失 | unittest 唯一用例被跳过，compact 仍返回 `status=passed, tests=1`，没有 skipped 字段；实际执行 0 项 | D1 |
| 未改动符号链接被报变化 | 创建副本后未编辑相对符号链接，却报告 `modified, source_conflict=true` | F1 |
| 第二次交付与自身冲突 | 同一文件首次交付 `applied`，再次修改交付得到 `source_changed_since_session_start` | F2 |
| 恢复摘要中的测试时效 | 基线 `resume()` 直接返回缓存的 `last_test`；读取路径不重新验证代码，也没有统一写入失效路径。第一批已补失效和恢复回归 | D2 |
| 后台测试证据不完整 | 当前测试观测只对 `exec_command` 捕获，未形成与后台启动、完成事件同等的证据链。代码路径确认，生命周期复现待补 | D3 |
| 启动成功但回复丢失后的采集恢复 | `edit()` 在传输失败时返回，尚未 `track_job()`；`ensure()` 遇本地句柄缺失直接返回。缺口路径确认，未做真实断线注入 | C2 |

已有的禁止 SSH 正常回退、任务原目标路由、进程组监督、幂等键、增量日志、有限等待、私有副本和审计需要沿用，不列为从零实现的能力。

## 工作包

优先级：P0 为会误导结论、阻塞基本流程或影响后续目录行为的前置项；P1 为日常可靠性与迁移；P2 为有基线后再验证的扩展。下列交付物都是具体提交范围，不意味着当前已实现。

### A：工作区与实际目录

| ID / 优先级 | 实现范围与交付物 | 依赖 | 验收 |
|---|---|---|---|
| A1 / P0 | 定义并实现显式 `binding_mode=direct\|copy`，登记源目录、实际 cwd、状态根、资源 ID 和格式版本；路由器/registry/API/文档一起更新 | 先完成模式与迁移契约；D2 已完成且未改 schema，A1 新增字段时独立设计兼容迁移 | direct 的 cwd 就是用户选择的规范目录；copy 仍创建私有副本；重启与切换后恢复相同模式；旧记录按 copy 解释 |
| A2 / P0 | 共享资源身份与跨聊天写入协调；工作目录资源与共享 Git 元数据资源分别处理 | A1 的数据契约 | 两个聊天通过不同路径别名访问同一资源不会静默覆盖；不同 worktree 文件互不混淆，共享 Git 写操作得到协调；控制/停止入口不被写锁阻塞 |
| A3 / P1 | 验证 direct 日常流程，随后把新建目标默认值切到 direct；保留明确的 copy 选项和兼容路径 | A1、A2、F3；D1/D2 已修复 | 三类使用方式全部通过；旧会话不自动改绑，丢失目录不隐式重建；新聊天仍默认本地 |

A2 的范围要先说清：第一阶段协调同一台本地控制端的多个 MCP 进程/聊天，并用内容或版本保护防范外部修改。它不自动成为多台控制端的分布式锁。`host alias + realpath`、仓库 URL、跨节点的 `dev/inode` 均不能单独证明 AFS 资源身份；不能确认时使用明确的存储命名空间映射或拒绝共享并发写。任意 shell 和后台作业可能写文件，不能只给 `patch_file` 加锁就宣称完成协调。

### B：认证与权限

| ID / 优先级 | 实现范围与交付物 | 依赖 | 验收 |
|---|---|---|---|
| B1 / P0 | 将现有复用限制固化为回归：无 socket、陈旧 socket、认证失效、目标别名异常；核验启动和控制通道的实际参数 | 无 | 正常路径不接触密码；复用失败不尝试新认证；失效后不会把远端任务改为本地执行 |
| B2 / P1 | 写明凭据、socket、审计和项目目录的权限边界；检查只读元数据、异常参数脱敏与日志权限 | B1；与 F4 的存储策略对齐 | 不读取密码内容；不把 0600 误称为同 UID 隔离；凭据不进入命令/审计；更强进程或账户隔离作为独立选项 |

不把替换用户的 `sshpass -f` 人工登录流程列为前置条件。AFS 访问、SSH 会话、原节点任务存活分别观测；其中一个正常不证明另两个正常。

### C：任务执行与恢复

| ID / 优先级 | 实现范围与交付物 | 依赖 | 验收 |
|---|---|---|---|
| C1 / P0 | 修复 `log_search.py` 小结果预算下的游标停滞；补字节游标、重叠匹配、转义/多字节上下文回归 | 无 | 每页有匹配时游标严格前进，或明确报不可满足预算；有限次数可读完；不漏匹配、不重复无限循环；不增加 SSH 调用 |
| C2 / P1 | 从不可变作业原目标恢复本地句柄与采集器，覆盖远端已启动但成功回复丢失的情况 | B1；保留现有幂等映射 | 不再提交同一任务；恢复日志游标与 `job_wait`；原节点/身份不匹配时明确 unknown；不能把本地句柄缺失当作远端任务已结束 |
| C3 / P1 | 组合验收 MCP 重启、采集器重启、断线重连、目标切换和取消；补清楚的状态转移与恢复入口 | C2；与 D3 集成 | 取消请求、取消确认、无法确认可区分；不按“Agent 最近是否读过日志”判断后台任务该不该结束；长前台命令不阻塞控制入口 |
| C4 / P2 | 仅在 GDB、ROOT/Python REPL 等实际交互需求出现时评估 PTY；先查依赖、许可和可复用点 | 普通任务路径稳定；有明确使用场景 | PTY 有独立会话/清理契约；普通命令仍能获取可靠退出码；安静输出不视为完成 |

进程组只保证其管理范围内的尽力清理；不承诺逃逸后代全部终止。幂等启动也不等于任意 shell 具有 exactly-once 语义。共享登录节点验收不使用递归 preload/spawn 测试。

| D5 / P1 | 审计视图关联执行位置、修改目的、差异、测试计数/时效、任务状态和证据读取位置 | D1–D3；字段契约稳定 | 原始事实与摘要一致；截断、过期、跳过、环境缺失、取消不确定性可见；完整 stdout/stderr/diff 能按记录定位 |

### E：独立基准工具与按需模型实验

| ID / 优先级 | 实现范围与交付物 | 依赖 | 验收 |
|---|---|---|---|
| E1 / P2 | 保留已有离线逐请求账本格式、解析器和完整性报告，作为独立基准的测试辅助工具；不新增在线模型调用 | 按需手动运行；可与日常开发完全分开 | 唯一请求不重复计数；输入/缓存/输出、模型/速度/费率版本、失败/重试、主/子 Agent、证据来源均可追溯；unknown 不记为 0 |
| E2 / P2 | 按明确需求手动建立同需求、同冻结代码、同独立验收的完整任务基准；实验允许两臂请求数不同 | E1；仅在独立基准实验中使用 | 分别报告总 token、费用、耗时、返工及计量覆盖率；保留历史样本；2% 只作为 token 基准阈值，不定义费用目标，也不阻止普通任务完成 |
| E3 / P2 | 按明确需求开展一个辅助场景的 Sol 对照 Sol+Luna 独立实验，例如失败日志证据提取；定义输入、输出、升级和费用停止条件 | 手动独立实验；如需费用比较则使用 E2 的实验协议；C/D 的证据读取可靠 | 计入交接、复核、失败和返工后再判断省费；Luna 直接读取获准的最小证据，不先让主模型读完整日志再转述；不伪造父聊天身份，实测子任务权限/工具/记录归属 |

E1 应区分 `actual_credit_debit`、有费率来源的 `estimated_credits` 和未知值。速度或费率缺失时不得将 Standard 折算写成实际扣减；API 费用单列原币种。仅在用户或项目明确启动独立实验时，才汇总实验执行、协调、子模型、复核、准备、诊断试跑与报告开销；不将这些实验计量接入日常命令、编辑、测试或回复/UI。

费用与订阅内用量也不能互相替代。官方说明见 [Pricing](https://learn.chatgpt.com/docs/pricing)。子 Agent 可配置模型，但继承父级权限/MCP；模型分工不是新安全边界，见 [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)。这两项是计量和边界依据，不证明本项目的多模型方案已经省费。

## 依赖与实施批次

1. **第一批：修复可信度并建立契约。** C1、D1、D2 各一个修复提交；完成 A1/A2 的身份、模式和迁移设计。已有 E1 仅作为可选离线基准工具，不进入日常工作流或本批主线。
2. **本轮限定三个行为提交：D1 补充修复 → C2 → D3。** D1 单独修正 subTest 的计数语义；C2 接回原后台任务及日志；D3 在启动时登记测试尝试，由采集/恢复流程补齐终态。C2/D3 共用的 Session、Registry 与采集调用链由同一负责人串行实施，分别审阅提交；定向测试后只做一次必要的完整集成回归。
3. **紧接的一批：A1 显式 direct ＋ A2 资源协调。** 数据结构、迁移和路由可拆提交；可写 direct 对外可用时必须同时具备文件、普通 shell、后台任务的资源协调，查询/日志/停止保持响应。实施前补齐重叠目录的资源根、共享 Git common-dir 的 worktree 并行范围、失去确认的资源占用核验与解除三个决定，并处理新旧 MCP 并存写入。沿用[现有契约](workspace-mode-contract.zh-CN.md)，不在本轮扩大设计或提前开放 direct。
4. **后续兼容、界面和发布验收。** F1/F2、旧副本盘点/迁移 F3、状态与存储 F4、组合恢复 C3、D4/D5、F5 按依赖继续拆小；A3 默认切换到 direct 在显式模式和必要迁移验收之后独立提交。旧调用、聊天、副本及任务保持兼容。功能正确性、证据准确性和 develop CI 仍是发布要求，费用基线不作为前置条件。
5. **按需独立实验：** 有明确需求时手动运行 E2 或 E3；实验结果只用于相应基准或模型分工研究，不改变普通任务的完成条件。C4 和更强账户/进程隔离按真实需求单列。
